# 每日回归完整性、日志状态与复测

## 每日计划

Clock 从 Tasks.yaml 和 templates 生成计划，固定本轮 ZIP、案例、flow_config、
提交幂等键和每条 YAML 任务的计划数量。先保存本地计划，再一次性发布全部批次
元数据到 Server SQLite。发布确认前不提交任何案例。

GUI 的“每日回归 → 比较日 · 回归完整性”按 YAML 任务展示：

- 计划 / 已提交 / 未提交数量。
- 排队或运行、执行结束、取消数量。
- 当前 run 的完整文件集校验数量、归档到期数量。
- 未提交、部分提交、执行中、执行完成、停止中、已停止后续、数量异常。

700 个计划案例只提交 600 个，即使全部结束，也不会显示整批完成。
执行状态来自同一 Scheduler 快照；日志收据是另外读取的实时状态，两者不承诺
跨文件系统事务一致。分页也是实时查询，应刷新确认。

旧日期没有发布记录时显示“不确定”：可能 Clock 未执行，也可能来自旧版本，
不能凭空宣称定时器正常或失败。一个日期只允许一份不可变计划；
故障后保留并续用 clock_state_file 及其 .plan.json，不要删除它们重新提交。
计划 SHA-256 标识保存的完整提交方案；进度按批次计数与幂等提交统计，
不是对运行目录内容的重新扫描。停止后续不会终止在途案例。

## 日志

任务详情 → 原始 run：可以刷新查看上传、Server 完整文件集校验、
Worker 清理确认和归档到期。未收到清单不能推断成已过期；
没有原始 run 也不能推断 GalaxCore 成功或失败，需查看采集说明。

超过旧 GUI 64 MiB 限制的文件可以分块下载。网络中断后重新选择同一目标文件，
自动匹配续传信息并校验已下载前缀；全文件 SHA-256 通过后才替换目标。
当前归档协议单文件上限仍是 1 GiB，超出不自动删除 Worker 日志。
旧历史归档没有 SHA-256 收据时仍可在警告确认后完整下载，但不标为已校验，
也不允许拿未校验的部分文件续传。

## 失败 / 超时复测

任务管理 → 批次详情，使用结果和路径筛选，然后点击“复测筛选中的失败 / 超时”。
覆盖当前筛选的全部失败或超时案例，不只表格本页；操作前会显示数量并二次确认。

GUI 先读取所有原任务的完整配置，全部准备成功后才提交。每个案例继承自己的
ZIP 版本、flow_config、优先级和超时，不使用当前模板覆盖历史配置。
原配置缺失则整批准备失败，请在“添加任务”里明确选择。

生成新的人工批次；suite 字段记录 rerun-task-原task_id。原结果不覆盖，
人工复测不参与每日日期对比。遇到提交响应丢失，可选择使用原幂等键继续提交；
选择放弃则已接收的部分保留，稍后可在任务管理查询或停止后续。
关闭 GUI 后不自动恢复未发送的复测请求，先检查已生成批次，不要盲目重建。

## 部署 / 验证

本轮需要同时更新 Server、GUI、Clock 和 Worker。配置字段不增加。
迁移到 schema v5 前备份 SQLite；旧二进制回退使用升级前备份，不降级活动 DB。

单机离线自测：在 build 目录执行 ctest --output-on-failure。
新增 test_daily_plan_process 覆盖部分提交、丢 ACK、续提交和 Server 重启；
test_qt_archive_download 覆盖大于 64 MiB 的下载、已有前缀续传、
错误身份 / 数据损坏 / 断网时保留目标，以及复测快照语义。
test_log_io_process 验证真实 TCP 上传、校验、Worker 清理确认和重启后读取。
这些不是内网真实 GalaxCore 或 Python 3.6.8 运行验收。
